## 1. 개요 및 국정원 보안성 검토 근거

### 1.1 점검 목적

- iCReaT에 저장된 연구과제 정보, 연구대상자 개인정보 및 임상·건강정보(민감정보)에 대한 접근 통제가 설계대로 작동하는지 확인함
- G-Cloud 환경에서 외주 개발·운영 구조로 인해 발생할 수 있는 비인가 접근 경로를 식별함
- 국가정보원 보안성 검토 및 개인정보 안전성 확보조치 기준 이행 여부를 사전에 점검하여 검토 지적 사항과 법적 위험을 최소화함
- 외주 운영사로부터 서면 증빙을 확보하여 통제 수준을 객관적으로 입증함

### 1.2 점검 대상 시스템 현황

| 구분 | 내용 |
| --- | --- |
| 서비스 주소 | https://icreat2.nih.go.kr/icreat2/invoke/CM000000/login/v2?langtp=K (사용자 로그인 페이지) |
| 취급 정보 | 연구과제 정보, 연구대상자 개인정보, 임상·건강정보(민감정보) |
| 권한 체계 | 일반 과제 담당자(소속 단일 과제만 조회·다운로드), 최고 관리자(전체 과제 통합 조회·일괄 다운로드) |
| 인증 방식 | 계정·비밀번호 인증, 3개월 주기 비밀번호 변경 정책 적용 |

| 인프라 | G-Cloud(공공 클라우드) |

### 1.3 점검 범위 및 한계

- **점검 방식**: 본 보고서는 문서·설정 검토 및 외주사 서면 소명 기반의 방어적 자체 점검 결과임
- **점검 한계**: 운영 시스템에 대한 직접 침투 시험은 포함하지 않음
- **외부 관찰 범위**: 서비스 주소의 로그인 페이지를 일반 사용자와 동일하게 1회 열람하여 응답 헤더, 전송 구간, 쿠키 노출, 사용 라이브러리, 페이지 소스를 수동 관찰함(2026. 11. 5.). 로그인 시도, 파라미터 조작, 비공개 경로 탐색, 반복 요청은 수행하지 않음. 결과는 1.5절에 기술함
- **관찰 한계**: 권한 검증, 세션 관리, 다운로드 로직, 감사로그 등 로그인 이후 서버 동작은 외부 관찰로 판단할 수 없으므로, 2장은 시스템 구조 정보와 점검 기준에 근거한 점검 항목임
- **후속 조치**: 필요 시 승인된 범위 내에서 전문기관 모의해킹을 별도 수행함
- **시나리오의 성격**: 2장의 예상 위협 시나리오는 취약점 존재를 확인한 것이 아니라, 점검 및 증빙 확인이 필요한 가능성을 기술한 것임

| 위험도 | 정의 | 조치 시점 |
| --- | --- | --- |
| Critical | 대량 개인정보 유출 또는 시스템 통제권 상실로 직결될 수 있음 | 즉시~단기 |
| High | 단독 또는 다른 취약점과 결합 시 중대한 유출·침해로 이어질 수 있음 | 단기~중기 |
| Medium | 단독으로는 피해가 제한적이나 다른 공격의 성공 가능성을 높임 | 단기~중기 |

## 2. G-Cloud 및 웹 애플리케이션 핵심 보안 점검 항목 (5대 축)

### 2.1 객체 수준 권한 검증 미흡 (BOLA / OWASP API1)

**① 위협 항목명 및 위험도**

- 과제·파일 식별자 조작을 통한 타 과제 임상데이터 수평적 무단 접근
- 위험도: **Critical**

**② 개념 및 현상 요약**

- 로그인은 "누구인가"(인증)만 확인하며, "이 자료에 접근할 자격이 있는가"(권한 확인)는 요청마다 서버에서 별도로 확인해야 함
- 서버가 요청에 포함된 과제 ID·파일 ID·대상자 ID가 요청자 소속 과제의 것인지 검증하지 않으면, 정상 로그인한 사용자가 식별자 값만 바꾸어 타 과제 자료에 접근할 수 있음
- 식별자가 순차 번호(1, 2, 3…) 등 추정 가능한 형식이면 위험이 커짐

**③ 국정원 보안성 검토 관점의 예상 위협 시나리오**

- 일반 과제 담당자가 조회·다운로드 요청의 과제 ID를 타 과제 값으로 변경하여 요청하고, 서버가 소속 여부 검증 없이 데이터를 반환함
- 과제 간 데이터 분리라는 설계상 통제가 화면 단에서만 구현되고 서버에서는 구현되지 않은 경우, 보안성 검토 시 "접근 권한 차등 부여 미흡"으로 지적될 수 있음

**④ 시스템 영향도**

- 데이터 유출: 단일 계정으로 전체 과제의 임상·개인정보 열람 및 반출 가능
- 법적 책임: 「개인정보의 안전성 확보조치 기준」의 접근 권한 관리 의무 미이행, 민감정보 유출 시 통지·신고 의무 및 과징금 대상
- 기관 신뢰: 국가 임상연구 관리체계 전반에 대한 신뢰도 저하

**⑤ 기술적·관리적 보완 요구사항**

- [기술] 모든 조회·수정·다운로드 API에 서버측 객체 소유·소속 검증 일괄 적용
- [기술] 외부 노출 식별자를 추정 불가능한 값(UUID 등)으로 전환
- [기술] 권한 판단은 클라이언트 전송값이 아닌 서버 세션 정보만을 기준으로 수행
- [관리] 과제별 접근 권한 부여·변경·말소 이력 관리

### 2.2 기능 수준 권한 검증 미흡 (BFLA / OWASP API5) 및 속성 변조 (Mass Assignment / OWASP API3)

**① 위협 항목명 및 위험도**

- 일반 계정의 관리자 API 직접 호출 및 파라미터 조작을 통한 수직적 권한 상승
- 위험도: **Critical**

**② 개념 및 현상 요약**

- 관리자 메뉴를 화면에서 숨기는 것은 표시 방식일 뿐이며 접근 통제가 아님
- 서버가 관리자 기능 요청마다 요청자의 역할을 확인하지 않으면, 정상 로그인한 일반 계정이 관리자 기능 주소로 직접 요청할 때 차단되지 않음
- 정보 수정 요청에 역할·권한 필드가 함께 전송될 때 서버가 이를 그대로 반영하면, 사용자가 스스로 권한을 상향할 수 있음

**③ 국정원 보안성 검토 관점의 예상 위협 시나리오**

- 일반 계정이 전체 과제 통합 조회, 일괄 다운로드, 사용자 관리 기능을 직접 호출하여 사용함
- 프로필·과제 정보 수정 요청에 권한 관련 필드를 추가 전송하여 관리자 권한을 획득함
- 보안성 검토 시 "관리자 권한 분리 및 통제 미흡"으로 지적될 수 있음

**④ 시스템 영향도**

- 시스템 통제: 최고 관리자 권한 탈취와 동일한 효과로, 계정·설정 변조 및 전체 데이터 일괄 반출로 이어짐
- 법적 책임: 접근 권한 관리 및 접근통제 의무 미이행
- 사고 대응: 정상 권한 행위로 기록되어 침해 여부 판단이 어려움

**⑤ 기술적·관리적 보완 요구사항**

- [기술] 관리자 기능 전 API에 서버측 역할 검증 적용 및 기본 거부(Deny by Default) 원칙 적용
- [기술] 수정 요청은 허용된 필드만 반영하는 허용 목록(Allow-list) 방식으로 처리
- [관리] 역할별 권한 매트릭스(역할 × 기능 × 허용 여부) 문서화 및 정기 검토
- [관리] 최고 관리자 계정 수 최소화 및 지정 사유 기록

### 2.3 백도어 및 외주사 관리 통로 (Shadow Access)

**① 위협 항목명 및 위험도**

- G-Cloud 접근 정책 미준수 및 정규 인증을 우회하는 외주사 관리 경로
- 위험도: **Critical**

**② 개념 및 현상 요약**

- 개발·유지보수 편의를 위해 만든 계정, 시험용 기능, 원격 접속 경로가 운영 전환 후에도 남아 있으면 정규 인증·권한 체계를 우회하는 경로가 됨
- 외주 인력이 계정을 공유하거나 퇴사자 계정이 회수되지 않으면 접속 주체를 특정할 수 없음
- 백업 데이터는 전체 데이터를 담고 있으나 운영 서버보다 통제가 느슨한 경우가 많음

**③ 국정원 보안성 검토 관점의 예상 위협 시나리오**

- 소스코드·설정파일에 포함된 관리용 계정, DB 비밀번호, API 키가 소스 또는 배포본 유출 시 직접 접근 수단으로 악용됨
- 개발 단계의 테스트 계정·디버그 엔드포인트·API 문서 페이지가 운영 환경에 잔존하여 내부 구조가 노출되거나 인증 없이 기능이 호출됨
- 원격 유지보수 경로가 G-Cloud 접근 정책(승인된 경로·IP·인증수단)을 벗어나 운영되거나, 공유 계정으로 사용됨
- 백업 데이터가 암호화 없이 보관되어 백업 저장소 접근만으로 전체 데이터가 유출됨

**④ 시스템 영향도**

- 데이터 유출: 인증·권한 통제 전체를 우회하여 전체 데이터 유출 가능하며, 정상 접근과 구분되지 않아 탐지가 어려움
- 책임 추적: 공유 계정 사용 시 행위자 특정 불가
- 법적 책임: 개인정보 처리 위탁자로서 수탁자(외주사) 관리·감독 의무가 있으므로, 외주사 관리 미흡으로 인한 사고도 기관 책임으로 귀결됨
- 보안성 검토: 클라우드 관리자 접근 통제 및 외부 접속 관리 항목 지적 가능

**⑤ 기술적·관리적 보완 요구사항**

- [기술] 소스코드·설정파일 내 하드코딩 비밀정보 자동 점검 및 제거, 별도 비밀정보 관리 체계 적용
- [기술] 운영 환경의 테스트 계정·디버그 기능·API 문서 페이지 제거 또는 접근 차단
- [기술] 원격 유지보수 경로에 개인별 계정, 다중 인증, 접속 IP 제한, 접속 기록 보관 적용
- [기술] 백업 데이터 암호화 및 백업 접근 권한자 최소화
- [관리] 외주 인력 계정 대장 관리, 투입·철수 시 계정 발급·회수 절차 문서화
- [관리] 사용 오픈소스·외부 라이브러리 목록 및 취약점 관리 현황 정기 제출

### 2.4 세션 및 계정 인증 관리 허점

**① 위협 항목명 및 위험도**

- 비밀번호 정책 회피, 대입 공격 차단 미흡, 세션 관리 부실, 관리자 2차 인증 부재
- 위험도: **High** (최고 관리자 계정 대상 시 Critical)

**② 개념 및 현상 요약**

- 3개월 주기 비밀번호 변경은 그 자체로 계정 탈취를 막지 못함
- 로그인 실패 횟수 제한이 없으면 반복 대입으로 비밀번호를 알아낼 수 있고, 타 서비스에서 유출된 계정 정보를 그대로 시도하는 공격에도 취약함
- 로그인 후 발급되는 세션(로그인 상태 정보)이 재발급·만료·폐기되지 않으면 탈취된 세션이 장기간 재사용됨
- 주기적 변경만 강제하고 복잡도·재사용 기준이 약하면 숫자만 바꾸는 등 예측 가능한 비밀번호가 늘어남

**③ 국정원 보안성 검토 관점의 예상 위협 시나리오**

- 실패 횟수 제한·계정 잠금 부재로 자동화된 반복 시도에 의해 계정이 탈취됨
- 로그인 전후 세션 식별자가 재발급되지 않아 세션 고정이 발생함
- 세션 타임아웃 미설정, 로그아웃 시 서버측 세션 미폐기로 탈취된 세션이 재사용됨
- 최고 관리자 및 외부 접속 계정에 2차 인증이 없어 비밀번호 단일 요소 탈취만으로 전체 시스템이 노출됨
- 보안성 검토 시 "인증 강도 및 외부 접속 인증수단 미흡"으로 지적될 수 있음

**④ 시스템 영향도**

- 데이터 유출: 탈취된 계정은 정상 사용자로 인식되어 해당 권한 범위의 데이터가 탐지 없이 유출됨
- 시스템 통제: 최고 관리자 계정 탈취 시 단일 실패 지점이 됨
- 법적 책임: 「개인정보의 안전성 확보조치 기준」의 인증 실패 시 접근 제한, 외부 접속 시 안전한 인증수단 적용 의무 미이행

**⑤ 기술적·관리적 보완 요구사항**

- [기술] 로그인 실패 허용 횟수 제한, 계정 잠금, 자동화 방지 장치 적용
- [기술] 최고 관리자 및 외부 접속 계정에 다중 인증(MFA) 의무 적용
- [기술] 로그인 시 세션 재발급, 유휴 시간 자동 종료, 로그아웃 시 서버측 세션 폐기, 동시 접속 제어
- [기술] 쿠키 보호 속성(Secure·HttpOnly·SameSite) 및 HTTPS 강제(HSTS) 적용
- [기술] 비밀번호 일방향 암호화 저장 확인
- [관리] 비밀번호 길이·복잡도·재사용 금지 기준 강화 및 주기적 변경 정책의 실효성 재검토

### 2.5 감사로그 및 이상행위 모니터링 결함

**① 위협 항목명 및 위험도**

- 대량 다운로드 및 관리자 행위 접속기록 누락, 로그 변조 방지 부재, 실시간 경보 체계 미흡
- 위험도: **High**

**② 개념 및 현상 요약**

- 접속기록은 누가·언제·어디서·어떤 자료에 대해·어떤 업무를 수행했는지 남겨야 하며, 로그인 기록만으로는 데이터 반출 여부를 확인할 수 없음
- 로그를 관리자 권한으로 수정·삭제할 수 있으면 침해자나 오·남용자가 흔적을 지울 수 있음
- 로그가 있어도 경보 규칙과 검토 주체가 없으면 침해를 실시간으로 인지하지 못함
- 최고 관리자는 전체 접근이 정상 권한이므로, 정상 업무 범위의 기준선이 없으면 오·남용을 구분할 수 없음

**③ 국정원 보안성 검토 관점의 예상 위협 시나리오**

- 조회·다운로드·권한 변경·설정 변경 행위가 로그에서 누락되어 사고 발생 시 유출 범위와 시점을 특정하지 못함
- 로그가 운영 서버에만 저장되어 침해 후 삭제·변조됨
- 야간 관리자 접속, 비승인 IP 접속, 평소 대비 급증한 다운로드가 발생해도 경보가 없어 장기간 미인지됨
- 로그 검토 주체와 운영 주체가 동일(외주사)하여 실질적 점검이 이루어지지 않음

**④ 시스템 영향도**

- 피해 확대: 2.1~2.4 모든 위협에 대한 탐지·대응·원인 분석을 불가능하게 하는 증폭 요인
- 법적 책임: 개인정보처리시스템 접속기록의 보관 및 정기 점검은 「개인정보의 안전성 확보조치 기준」의 의무사항으로, 미흡 시 그 자체로 법적 미준수
- 사고 대응: 유출 범위 특정 불가 시 정보주체 통지 및 기관 신고를 정확히 수행하기 어려움

**⑤ 기술적·관리적 보완 요구사항**

- [기술] 접속기록 항목 표준화(계정·접속일시·접속지·처리 정보주체·수행 업무)
- [기술] 로그를 운영 서버와 분리된 저장소에 보관하고 변조 방지(WORM) 적용
- [기술] 이상행위 경보 규칙 수립(야간 관리자 접속, 비승인 IP, 대량 다운로드, 권한 변경) 및 기관 담당자 동시 수신
- [관리] 법정 보관기간 이상 보관 및 월 1회 이상 접속기록 정기 점검
- [관리] 기관 담당자가 직접 로그를 열람·점검할 수 있는 수단 확보, 점검 결과 기록

## 3. 국정원 보안성 검토 대비 외주 운영사 제출 요구 서면 증빙 체크리스트

| 15 | 이상행위 경보 및 정기 점검 | [문서] 경보 규칙 목록, 수신자 목록 / [로그] 최근 경보 발생·대응 이력 / [문서] 최근 취약점 진단 보고서 및 조치 이력 | 기관 담당자에게도 경보가 전달되는지, 지적 사항이 모두 조치되었는지 |

### 3.3 회신 검토 기준

- 증빙 없이 "조치 완료"만 회신된 항목은 **미확인**으로 분류하고 재요청함
- "확인 불가" 또는 "기록 없음"으로 회신된 항목은 **통제 부재**로 간주하여 즉시·단기 조치 대상에 포함함
- 미조치 항목은 완료 예정일 기준으로 이행 여부를 재점검함

### 4.4 이행 관리

- 단계별 완료 여부는 외주사 제출 증빙으로 확인하며, 증빙이 없는 항목은 미완료로 관리함
- 월 1회 이행 현황을 점검하고, Critical 항목 지연 시 상위 보고함
- 운영 시스템에 대한 직접 시험은 승인된 범위에서 보안 담당 부서 또는 전문기관이 수행함
